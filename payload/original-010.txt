>
  <div class="steps">
    <div class="step"><strong>Open the repositories.</strong> Add the frontend, API and shared library folders to one Codex task.</div>
    <div class="step"><strong>Analyse without editing.</strong> Ask Codex to reproduce the failure, map dependencies and identify the likely root cause.</div>
    <div class="step"><strong>Define safety boundaries.</strong> State which files may change, which commands are allowed and which actions require approval.</div>
    <div class="step"><strong>Create isolated branches.</strong> Use a dedicated branch or worktree per repository.</div>
    <div class="step"><strong>Implement the smallest compatible fix.</strong> Preserve public interfaces unless the evidence requires a coordinated change.</div>
    <div class="step"><strong>Test across repositories.</strong> Run unit, integration, contract and regression tests and compare before/after behaviour.</div>
    <div class="step"><strong>Review the diff.</strong> Ask for a security, performance and backward-compatibility review.</div>
    <div class="step"><strong>Stop before publishing.</strong> Require human approval before push, pull request, deployment or destructive command.</div>
  </div>
  <div class="prompt"><div class="prompt-title">Analysis-only prompt</div><pre>Analyse the checkout regression across the frontend, API and shared-library repositories. Do not modify files yet. Reproduce the issue, identify the root cause, list affected interfaces, propose the smallest compatible fix and define the test plan. Separate evidence from hypotheses.</pre></div>
  <div class="prompt"><div class="prompt-title">Implementation prompt after approval</div><pre>Apply the approved fix in isolated branches. You may edit only the listed files and run the approved test commands. Show progress and every meaningful diff. Stop and ask before installing new dependencies, changing public APIs, pushing, opening a pull request, deploying or deleting data.</pre></div>
